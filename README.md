# Hi, I am Vivek

I build software from the screen to the server. One day it is a React dashboard that must load fast. The next day it is a queue that must not lose a message, or an LLM agent that must call the right tool.

I like the hard questions between systems. What happens to a request when a service fails? Why is this page slow? What does the model do when it does not know the answer?

## What I believe about software

- **Plan for failure.** Networks fail, services fail, and users send bad input. I design for retries, timeouts, and safe failure before the first deploy.
- **Measure, then change.** I find the slow part with data before I change the code.
- **Write for the next engineer.** Clear code is easier to fix at 2 a.m. than clever code.
- **Make AI honest.** An AI feature that gives a wrong answer with confidence is worse than one that says "I do not know."
- **Add security at the start.** Authentication, access control, and input validation are part of the design, not a final step.
